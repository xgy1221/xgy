# 学管云 · 可售卖产品设计说明

本文记录：**原先哪里乱 / 欠考虑**，以及**怎么改成能卖的教培小程序产品**。

---

## 1. 原先不合理的地方

| 问题 | 为什么不行 | 改进方向 |
|------|------------|----------|
| 小程序 / Web / 后端三套假数据互不相通 | 演示能点，没法交付客户 | 后端 MySQL 为唯一真相；前端逐步接 API |
| 家长底栏一度 4 个、功能堆在「我的」 | 课次多时刷屏，找不到报名/评价 | 三栏：课表 / 比赛 / 我的；我的内「切孩子→切教案→课次」 |
| 比赛页不切孩子 | 跨机构家长容易报错孩子 | 比赛页同步孩子切换 |
| 合伙/管理小程序菜单过重 | 手机不适合做财务配置 | 手机只看快览；改权限/财务走 Web |
| 后端无比赛表、无课次按教案查询 | 家长「我的」评价列表落不了库 | 补 `activities` / 报名表 + lesson 查询 API |
| 报读无「已上」字段返回 | 前端各算各的 | API 统一返回 `usedLessons` / `progress` |
| 角色名不一致（student vs PARENT） | 对接必炸 | 约定映射表，文档写死 |
| 缺少软删除 / 教案下架语义 | 误删无法恢复 | `deleted_at` / `status` 并存 |

## 2. 可售卖产品定位（一句话）

**多机构教培 SaaS**：家长看课表与比赛、看课次与老师评价；老师上课临补消课；教务/合伙/管理在 Web 管教案、排课与财务。

### 端分工（卖点级清晰）

```text
家长小程序          老师小程序           教务小程序         Web 管理端
课表 / 比赛 / 我的   课表 / 班级 / 学员    报名代录 / 课表     教案·学员·排课·财务
看评价·报比赛        临补·评价消课         轻量现场            合伙看分成，管理定权限
```

### 家长三栏（定稿）

1. **课表**：首屏是**下一节课**（机构语境 + 孩子），月历下沉；空日有「去看下一节」  
2. **比赛**：机构办的竞赛/展示；报名参赛 / 往期 / 已报；**可切孩子**；卡片 CTA「为某某报名」  
3. **我的**：首屏是**教案进度 + 最近老师评价**；账户/切角色/退出收进头像抽屉

不在底栏堆「全部课次 / 教案列表」——入口放在「我的」文末链接即可。

### 家长端产品体验原则（本迭代落地）

| 原则 | 做法 |
|------|------|
| 登录后品牌是机构 | 导航栏 / 页头显示机构名；「学管云」留给登录页 |
| 首屏一件事 | 课表=下一节；我的=进度与评价；比赛=为当前孩子报名 |
| 少工具感 | 账户设置不占首屏；演示账号折叠；家长文案不用运维口吻 |
| 空状态可行动 | 没课 → 跳下一节；没教案 → 说明教务会代录 |
| 动效服务流程 | 进场 rise、切孩子/Tab 淡入淡出、底栏选中点、按压缩放；忌炫技 |

### 关键操作流（验收手感）

1. 登录 →（多角色则选身份）→ 家长落在课表「下一节」  
2. 切孩子：轻震 + 内容淡出淡入，导航栏机构名跟着变  
3. 比赛报名：确认弹窗 → 成功 toast + 底栏脉冲 → 状态变「已报名」  
4. 我的：切教案淡入进度与最近评价；头像展开账户抽屉  
5. 老师课表：今日/下一节进课堂 → 临补搜索加入 → 下课评价消课

## 3. 多机构模型（卖多家时必讲清）

```text
机构 org（租户）
  └─ 校区
  └─ 员工（教务/老师/合伙/管理）← 一人绑定一家机构
  └─ 学员 / 教案 / 报读 / 班级 / 课次 / 订单 / 比赛 / 白名单

家长手机号（全局）
  └─ 可在多家机构各有学员档案（同名孩子两份）
  └─ 切换孩子 = 切换机构上下文
```

**硬规则：** 禁止跨机构绑教案、临补、报比赛。

---

## 4. 核心业务闭环（交付验收用）

1. 教务：上架教案（课次数+售价）→ 建学员 → 建班 → 日历订课  
2. 老师：日历上课 → 临时插班（不改原班）→ 评价学生 → 自动消 1 课  
3. 家长：看课表 → 在「我的」按教案看已上进度与老师评语 → 报名比赛  
4. 合伙/管理：Web 看实收/退费/分成（教务不开放完整财务）

## 5. 角色 ↔ 系统值映射

| 产品角色 | 小程序 role key | 后端 RoleType | Web role |
|----------|-----------------|---------------|----------|
| 家长/学生 | `student` | `PARENT` | — |
| 老师 | `teacher` | `TEACHER` | — |
| 教务 | `academic` | `ACADEMIC` | `academic` |
| 合伙人 | `partner` | `PARTNER` | `partner` |
| 管理员 | `admin` | `ADMIN` | `admin` |

课次状态：前端可用 `upcoming/ongoing/finished`，后端存 `SCHEDULED/ONGOING/FINISHED`，对接层做映射。

## 6. 数据表（后端 Flyway）

已有：`orgs` `campuses` `users` `user_roles` `students` `course_packages` `enrollments` `teachers` `classes` `class_students` `lessons` `lesson_attendees` `orders` `phone_whitelist`

补齐：

- **`activities` / `activity_signups`**：比赛报名与往期回顾  
- **`lessons.package_id`**：方便按教案查课次与评价  
- **软删除字段**（学员/教案等 `deleted_at`）  

详情见 `backend/src/main/resources/db/migration/`。

---

## 7. 小程序 ↔ 后端对接（本迭代）

- `miniprogram/services/api.js`：`useRemote: 'auto'`，探测 `GET /api/ping`  
- `miniprogram/services/bridge.js`：登录 JWT → 水合学员/报读/课次/比赛到本地 storage；失败回退 mock  
- 角色映射：`student↔PARENT` 等（见上表）；课次 `SCHEDULED→upcoming`  
- 写透：切孩子 / 切角色 / 比赛报名取消走远程；「我的」教案课次优先 `student-package`  
- 真机请把 `api.config.baseUrl` 改成电脑局域网 IP，开发者工具勾选不校验合法域名  

## 8. 本迭代不做（避免摊子过大）

- 微信支付 / 退费审批流（订单表先记账，Web/教务可录单）  
- 微信订阅消息课前提醒  
- 作业批改 / 成长相册  
- 平台级超管（跨机构开通租户）  
- 小程序原生 `tabBar` 改造（现自定义底栏可先用）  
- ~~Web 管理端接同一后端~~（已打通）  
- ~~安全基线~~（限流 / 白名单 / RBAC / CORS / 审计，见 `docs/SECURITY.md`）

## 9. 验收清单（能不能卖的最低线）

- [x] 两家机构数据互不可见（JWT orgId）  
- [x] 家长切孩子后课表/比赛/教案评价跟着变  
- [x] 老师评价学生后家长能在「我的」看到  
- [x] 比赛能报名/取消，往期能看赛果  
- [x] Web 教务能建教案与排课；合伙能看财务摘要  
- [x] 后端 Flyway 一键起库，小程序可 auto 对接 JWT API  
- [x] Web 报读 / 白名单 / 活动 / 授权 / 审计  
- [x] 新家长未加白名单不可登录
