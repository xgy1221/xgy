# 学管云 · 产品结构建议

## 多机构隔离（租户）

产品可能被**多家教培机构**同时使用；家长同一个手机号也可能在多家机构给孩子报课。隔离边界是 **`orgId`（机构）**，校区是机构内部概念。

```text
机构 orgId（租户边界）
  └─ 校区
       └─ 学员 / 教师 / 教案 / 班级 / 课次 / 订单 / 白名单
```

| 对象 | 隔离规则 |
|------|----------|
| 员工（教务/老师/合伙/管理） | 登录绑定**一家机构**，列表与写入只看本 `orgId` |
| 家长手机号 | **可跨机构**（全局身份） |
| 学员档案 | `orgId + 手机号 + 姓名` 唯一；同名孩子可在多家机构各有一份 |
| 教案 / 报读 / 班级 / 课次 / 财务 | 严格按机构；禁止跨机构绑教案或插班 |
| 手机号白名单 | 按机构分行；同号可出现在多家名单 |

家长端：切换「孩子」即切换机构上下文（chip 显示 `王一诺·学趣` / `王一诺·启航`）。  
员工端：永远不拉其它机构的学员/财务。

演示机构：`org_xuequ` 学趣思维 · `org_qihang` 启航英语。  
跨机构家长：`13800000001`。启航员工：`13800000040`（教务）/ `41`（老师）。

## 你真正要管理的数据层

| 层级 | 叫什么 | 一句话 |
|------|--------|--------|
| 租户 | 机构 orgId | 数据隔离边界 |
| 账号 | 家长手机号 | 谁能登录（可跨机构） |
| 档案 | 学员 | 某机构下家挂几个孩子 |
| 产品 | 教案 / 课程包 | 卖的是什么、含多少课次 |
| 报读 | 购买记录 | 哪个孩子买了哪个教案、还剩多少课 |

```text
家长手机号（可跨机构）
  ├─ [学趣思维] 学员 A / 学员 B → 报读 → 课次
  └─ [启航英语] 学员 A′ → 报读 → 课次
```

## 建档入口（并存）

1. **在读学员：老师 / 教务代录（主路径）**  
   - 按家长手机号建/改学员档案  
   - 直接绑定教案，并填写**剩余课次**（已经上过一部分课）  
   - 报读来源标记为「教务代录」或「老师代录」  
2. **机构批量先录**  
   - Excel 完整学员信息，或只录家长手机号（白名单）  
3. **家长自助（新客 / 未建档）**  
   - 授权登录后若还没有学员 → 分步引导添加学员 + 选教案  
   - 手机号从未录过 → 自动新建家长账号再引导  

原则：**已经在上课的，别让家长自己摸；老师教务弄好，家长打开就能看。**

## 多角色授权

- 同一账号可同时拥有：合伙人 / 教务 / 老师 / 管理员 等组合  
- 登录后若有多个角色：优先进入**上次选择的角色**；没有记录时先选一次  
- 之后在各端「我的」里可随时切换，并记住为下次默认  
- 典型场景：合伙人同时也是教务或老师

## 角色 × 端：市面教培常见分权

| 角色 | Web 管理端（电脑） | 微信小程序（手机） |
|------|-------------------|-------------------|
| **学生/家长** | 一般不需要 | **主战场**：日历课表、报读剩余、课后评价 |
| **老师** | 可选只读 | **主战场**：班级日历、临补、下课评价消课 |
| **教务** | **主战场**：教案/学员/教师/建班/日历订课 | 现场：报名、课表、查看评价；不开放完整财务 |
| **合伙人** | **财务中心**（本校区实收/退费/分成）+ 业务数据只读 | **轻量看板**：本月业绩/分成/热销教案；明细对账用 Web |
| **管理员** | **全量**：配置、账号权限、全校区财务 | **运营快览**：在读规模、收款健康度；改权限/审批走 Web |

设计原则（参考校管家、美校等教培 SaaS）：

1. **收款、分成、对账、导出**放电脑端，屏幕大、口径不容易点错  
2. **上课现场、家长触达**放小程序  
3. 合伙/管理若打开小程序：只给「巡店/外出瞄一眼」的指标，不把 Web 整套后台搬进手机  

### Web 三角色菜单差异

| 模块 | 教务 | 合伙人 | 管理员 |
|------|------|--------|--------|
| 工作台 | 运营 KPI | 运营 KPI + 财务摘要 | 全量 KPI + 财务摘要 |
| 学员 / 教师 / 课程 / 教案 | 可编辑 | 只读（看本校区） | 可编辑 |
| 财务中心 | ❌ | 本校区 + 本人渠道分成 | 全校区实收/退费/待收/结构 |
| 账号权限 | ❌ | ❌ | ✅ |

## 教案（课程产品）建议字段

- 名称、适用年级、总课次数、售价、状态（上架/下架）
- 大纲课次列表（第 1 课 … 第 N 课，可选）
- 以后再加：教材版本、科类、校区适用范围

教务日常：上架教案 → 看谁报了 → 排课消课。  
家长日常：看自己孩子报了哪些教案、剩余课次、课表。  
合伙/管理：透过财务中心看「哪个教案卖了多少钱」。

## 财务信息怎么做（合伙 / 管理）

教培后台常见财务看板（本仓库 Web「财务中心」已按此骨架）:

1. **签约额 / 实收 / 退费 / 待收（欠费）**  
2. **按校区汇总**净收  
3. **按教案产品**看销量与实收  
4. **报名订单流水**：学员、教案课次数、缴费状态、渠道  
5. **合伙人分成**：净收 × 分成比例（演示口径；正式环境可按校区/顾问/课时拆）  

教务不开放完整财务，避免运营与收款口径混在一起；需要核对课次时看课表与报读即可。

## 推荐家长引导步骤

1. 登录 / 授权手机号  
2. 填写家长称呼（可跳过）  
3. 添加至少两个孩子信息（可继续添加）  
4. 为每个孩子勾选已购教案（也可稍后在课程页补）  
5. 进入首页

## Web 管理端 vs 小程序

**Web（教务 / 合伙人 / 管理员）**

1. 创建教案：名称、科类、**包含多少节课**、售价  
2. 录入学员（家长手机号可多孩）、维护教师  
3. 课程管理：建班、绑教案与老师、加固定班学员、日历订课  
4. 财务中心：合伙人看本校区分成；管理员看全校与欠费  
5. 管理员：账号多角色授权  

**小程序**

1. **家长 / 老师 / 教务**：日历看课、临补、评价消课、代录报名（主路径）  
2. **合伙人**：业绩 / 分成 / 团队快览 → 详情引导 Web  
3. **管理员**：全校规模 + 收款健康度快览 → 配置引导 Web  

## 日历上课闭环

1. **家长/学生**：进小程序底部「课表」是日历，默认当天；有课日期打点，点日期看自己的课  
2. **老师**：同样是日历，但按**班级课次**展示，名单显示学生姓名  
3. **临时补课**：老师可把旷课学生临时插入本节课；只影响本节 `attendees`，**不改原班花名册**；后续教务排课仍按原班  
4. **下课消课**：老师点下课并评价学生 → 自动消 1 节课；**学生评价老师可选**，不评不影响消课  
5. **教务总览**：日历看每天哪个老师有课；点进课次只读查看「学生→老师 / 老师→学生」评价与消课情况  

## 以后课程管理怎么长

- **教案管理**：增删改教案、课次数、大纲  
- **报名/报读**：教务代录或家长自选；审核缴费状态  
- **排课**：从报读剩余课次里排（固定班）  
- **临补**：只挂本节，不改班籍  
- **消课**：下课互评完成后扣剩余  
- **分润结算**：订单实收进财务中心，按规则生成合伙人分成单  

先把「日历课表 → 上课 → 临补 → 互评消课」与「Web 建班订课 / 财务看板」跑通。
